Assumptions (spec left these open):
- so list prints a JSON array of so show objects, sorted by id, filtered by the derived status when --status is given. Invalid status is a user error.
- so pick picks entries carry sku, from, lot (null for non-lot products), serials (sorted), qty (string). Sorted by source location, then SKU, then lot.
- Lot order: earliest lot expiry first, then lot, then location. Lots with no expiry sort last. Lots that expired before today are skipped.
- Serial order takes the lowest serial numbers first within each location.
- Status: partially_shipped takes precedence over confirmed (spec order), so an order with a shipment and all lines reserved stays partially_shipped until fully shipped.
- allocate and confirm reserve only at storage locations of the order's warehouse. Stock already reserved by other open orders is skipped.
- Receiving a PO does not reserve stock for backordered orders; that happens only when allocate runs.
- so ship sets order_lines.shipped; reservations in state picked are deleted after ship. Cancel deletes all reservation rows and leaves physically picked stock in WH/SHIP, as the spec says.
- Hold: integer hours 1 to 720, default 48. Expiry is ctx.now + hold hours, stored in ISO format (same format as to_dt/from_dt).
- Backordered for available: sum over stored-confirmed orders (which covers derived backordered and partially_shipped) of qty not reserved, picked or shipped, for the SKU.
