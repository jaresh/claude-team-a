**Do not redo**
- Role/user checks: core.execute gives the same UserError for unknown user and for role failure, so http_api pre-checks in `_authorize` (401 vs 403). Do not remove it.
- `hold` in the confirm body accepts a JSON integer or a string (a JSON int is converted to str). Spec only requires quantities, amounts and costs to be strings, so this is intentional.
- Confirm is not all-or-nothing on stock: _reserve_order reserves what is available and backorders the rest. The competing-orders test asserts this, so it is not a double reservation. Do not "fix" it in http_api.
- 404 for an unknown product or order in the URL, and 400 for an unknown SKU or customer in a body (judgment call; the spec only defines 404 for objects in the path).
- PATCH: null for min or max maps to 'none'. name cannot be cleared (null becomes a string-type 400). Unknown keys 400. If-Match missing 428, mismatched 412, product checked before If-Match. `product edit` gets the version from the DB, so the handler checks it again inside the transaction.
- Receipts: body `at` is the WH/LOC location (the CLI's --at), not a time. Time is X-Now. `serials` must be a list of strings without commas, and is joined with ','.
- Known gap, not fixed: idempotency row is written after core.execute commits (core owns BEGIN/COMMIT, so it cannot share the transaction). A crash between the command commit and the INSERT means a retry re-runs the command. Fixing this needs core support.
- `serve` handler takes ctx=None (cli.py calls it without the lock), and uses args.db and args.port.
