**Known limitations / assumptions for README (lead)**
- The idempotency row is written in its own transaction after the command commits (core owns the command transaction). A crash between the two could re-run the command on retry. Not fixed; would need core support to share one transaction.
- The server lock makes check-then-run atomic only inside one server process. SQLite's BEGIN IMMEDIATE still serialises writes across processes, but two processes could both miss an idempotency key at once.
- Wrong method on a known path returns 404 (spec wording "404 for an unknown path").
- PATCH with an empty body -> 400 "nothing to change". Hold must be a JSON integer (a string "24" -> 400). Unknown query parameters are ignored. Unknown body fields -> 400.
- Receipt "at" is a location (see above); the request time is X-Now.
