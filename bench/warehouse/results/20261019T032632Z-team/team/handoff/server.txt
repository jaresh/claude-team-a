**Do not redo**
- `receive --at` is a location code (WH1/A-01), not a time. The receipts body field `at` is passed to `--at` as the location; the movement time comes from the X-Now header. I checked this against stock.py `_setup_receive` and the do_receive call. An earlier draft of the tests used a timestamp for `at`, which gave 404 (unknown location).
- Test setup goes through the CLI via `self.ok(...)` (in Wms.basic), so every test spends about 1.5 s on subprocesses. The 50 s run time is from that, not from the server. Speed-up option: build the fixture in-process with wms.app.execute.
- Concurrency: five 4-unit orders against 10 BOLT. The test asserts all confirms return 200, every line reserved in 0..4, and the sum is exactly 10. Shortfalls become backorders, so losing orders are not errors.
- Idempotency: the row is written after execute, in a separate autocommit connection, both under LOCK. A crash between the commit and the INSERT would leave the command applied without a stored response. This is a known window, not handled.
- Decisions to review (not spec-mandated): a malformed If-Match returns 412 (not 400); unknown query params are ignored; unknown body keys return 400; any UserError starting with `unknown ` returns 404 (this also covers an unknown SKU in a receipt body and an unknown customer in SO create); a method with no matching route returns 404 (no 405).
