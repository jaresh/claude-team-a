## Contract
Each cmd module exposes `register(sub)`; adds subparsers with `set_defaults(func=fn)`, `fn(conn, args)` returns a JSON-able value (or None); raise core.UserError for user errors (CLI exits 2). Amounts in output via core.fmt (two decimals, never "-0.00"). Money is Decimal, round half up via core.q2. Put logic in plain functions `f(conn, ...)` taking/returning Python values (so the HTTP server can reuse). Tests: tests/test_<module>.py using tests.helpers.CliCase (see tests/test_basic.py). Do not edit core.py, __main__.py, cmd_basic.py, helpers.py; if core needs a fix, note it in handoff and work around it. Only python3 (no `python`). Append edits to shared files to .claude/team/changes.md (you should only touch your own files).

## importer
Files: fin/cmd_import.py, fin/cmd_budget.py, fin/cmd_recurring.py, tests/test_import.py, tests/test_budget.py, tests/test_recurring.py.
- `rule add PATTERN ACCOUNT` (case-insensitive regex via re.search on description; invalid regex or unknown/invalid account -> UserError; account must exist), `rule list` -> [{"pattern","account"}] in order added.
- `import FILE --account ACCOUNT [--date-col N=0] [--desc-col N=1] [--amount-col N=2] [--skip-header]`: csv module; each row -> txn (core.insert_txn, commit=False; commit once at end; on any bad row roll back everything and raise UserError, nothing imported) between ACCOUNT (row amount) and category account: first matching rule's account, else Expenses:Uncategorized for negative / Income:Uncategorized for positive (core.ensure_account, book currency; amount 0 -> Expenses:Uncategorized). Dedupe against table `imported` (account,date,description,amount normalised via core.fmt), including repeats within the file. Skip blank rows. Missing file / bad col -> UserError. Output {"imported": N, "skipped": M}.
- `budget set ACCOUNT MONTH AMOUNT` (account must exist and be type expense; MONTH via core.parse_month; replace existing) and `report budget MONTH` -> [{"account","budget","actual","remaining"}] sorted by account; actual = sum of that month's postings to account and descendants (in the account's currency, Decimal sum), remaining = budget - actual. NOTE: `report` is a shared subcommand name with another teammate (reports). Therefore export `register_report(rsub)` in cmd_budget.py that adds `budget` to the `report` subparsers object `rsub`; reports teammate's cmd_reports.register creates the `report` parser and calls `cmd_budget.register_report(rsub)`. cmd_budget.register(sub) itself only adds `budget set`.
- `recurring add NAME --every monthly|weekly|yearly --start DATE --posting ACC=AMT ...` (validate with core.resolve_postings on add; store postings as JSON of [account, amount-string-or-null]) and `recurring run --until DATE`: create every occurrence from start through DATE inclusive not already in recurring_done, txn description NAME; second run creates nothing. Monthly: occurrence k = core.add_months(start, k) (keeps start's day, clamped); weekly +7k days; yearly = add_months(start, 12k) (Feb 29 -> Feb 28). Output {"created": N}.
Done check: python3 -m unittest tests.test_import tests.test_budget tests.test_recurring tests.test_basic (budget report test may call `report budget` only once reports teammate has merged; test it via calling cmd_budget functions directly meanwhile).

## reports
Files: fin/cmd_reports.py, fin/cmd_loan.py, tests/test_reports.py, tests/test_loan.py.
- cmd_reports.register(sub): creates `report` subparsers (dest="sub", required=True, parser_class same as sub's: use `type(sub.choices...)` or simply `sub.add_parser("report").add_subparsers(dest="sub", required=True)`), adds income, balance-sheet, networth, then does `from . import cmd_budget; cmd_budget.register_report(rsub)` inside try/except ImportError/AttributeError (module being written in parallel).
- Report amounts are in book currency or `--currency CUR`, each posting amount converted at the report's date (--to or --at; for networth the month's last day) with core.convert-like rounding per account total (convert each account's per-currency sum, then add); missing rate -> UserError. Income/liabilities/equity shown negated. Accounts listed by the exact account name the postings are on (not ancestors), only if they have postings in range (zero sum shows "0.00").
- `report income --from DATE --to DATE [--currency]` -> {"income":{acct:str},"expenses":{...},"total_income","total_expenses","net"}.
- `report balance-sheet --at DATE [--currency]` -> {"assets","liabilities","equity" (dicts),"retained_earnings","total_assets","total_liabilities","total_equity"}; postings up to DATE; retained_earnings = income - expenses (all up to DATE, negated raw sum of income+expense accounts); total_equity includes it; total_assets = total_liabilities + total_equity. Totals = sum of the displayed (rounded) entries so they always add up.
- `report networth --from MONTH --to MONTH [--currency]` -> [{"month","assets","liabilities","networth"}] one per month inclusive, as of month end; liabilities positive, networth = assets - liabilities. from > to -> UserError.
- Put report logic in functions `income_report(conn, date_from, date_to, currency=None)`, `balance_sheet(conn, at, currency=None)`, `networth(conn, m_from, m_to, currency=None)` returning the dicts (HTTP server will import them).
- `loan schedule PRINCIPAL RATE MONTHS --start DATE` (cmd_loan.py; function `schedule(principal, rate, months, start)` returning dict) per spec: r = RATE/1200 as Decimal (use decimal context prec 50); payment = P*r/(1-(1+r)^-n) rounded half up to cents (RATE 0: P/n); each month interest=q2(balance*r), principal=payment-interest; last row repays remaining balance (payment = balance+interest, principal = balance); final balance "0.00"; row n date = core.add_months(start, n); total_interest = sum of interest. Months must be >=1 int, principal>0, rate>=0 else UserError. Output {"payment","total_interest","rows":[{"n","date","payment","interest","principal","balance"}]}.
Done check: python3 -m unittest tests.test_reports tests.test_loan tests.test_basic

## server
Files: fin/cmd_serve.py, tests/test_serve.py, README.md.
- `serve --port N` (cmd_serve.register adds it; fn runs http.server.ThreadingHTTPServer on 127.0.0.1:N with serve_forever; open a new sqlite connection per request via core.connect(args.db)). Routes (JSON, Content-Type application/json): GET /accounts (core.list_accounts), GET /transactions (core.list_txns), GET /balances?at=DATE (core.balances), GET /reports/income?from=&to= (cmd_reports.income_report; import lazily; from/to required else 400), GET /reports/balance-sheet?at= (cmd_reports.balance_sheet), optional `currency=` query param on reports. POST /transactions body {"date","description","postings":[{"account","amount"?}]} -> 201 + txn via core.insert_txn (amount absent/null = blank posting; bad JSON/shape -> 400); UserError -> 400 {"error": msg}; unknown path -> 404 {"error":...}; wrong method on a known path 405. Silence request logging. Factor `make_server(db_path, port)` returning the server so tests can run it in a thread on port 0.
- tests/test_serve.py: start make_server in a thread, use urllib. Report endpoints may not exist until reports teammate merges: skip those tests with unittest.skipUnless(importable cmd_reports).
- README.md: how to use (every command with an example), how to run tests, and an "Assumptions" section. Include assumptions: non-JSON output is pretty JSON; amounts with >2 decimals rounded half up at entry; zero-amount allowed; DB must exist for all commands except init; currency codes upper-cased; fx rate must be >0; import is atomic (any bad row aborts all); import rules require existing accounts; reports use per-account-total conversion; budget requires expense account; uncategorized for zero amount is Expenses; recurring postings stored as given (blank posting resolved at run time); HTTP listens on 127.0.0.1; networth from>to is an error.
