Assumptions to record in README (decisions I made where the spec was silent):
- import: a row whose amount is 0 goes to Income:Uncategorized (since amount < 0 selects Expenses).
- import: rule patterns are matched with re.search, case-insensitive, first matching rule wins (rules ordered by id).
- import: unmatched rows go to Expenses:Uncategorized / Income:Uncategorized, created on demand with the bank account's currency.
- import: dedupe key is (account, date, description, amount) in the `imported` table, so identical lines within
  one file are also skipped on the second occurrence. Rows on a different account are not duplicates.
- import: any bad row (short row, bad date/amount, closed month) raises UserError before any post, so nothing is imported.
- rule add: account must already exist; pattern must compile as a Python regex.
- budget set: only expense accounts; month validated by parse_month; re-setting replaces the amount and audits each time.
- report budget: actual = sum of postings to the budget account and its descendants in that month, amounts summed as
  stored (assumes one currency per account tree). Budgets with no postings show actual 0.00.
- recurring add: postings checked at add time (>= 2 postings, at most one posting without amount, each currency balances
  except the currency of the balancing posting). Nothing is posted at add time.
- recurring run: occurrences from start; monthly keeps the start day, clamped to month end (Jan 31 -> Feb 28);
  yearly from Feb 29 -> Feb 28 in non-leap years; weekly every 7 days. Already-run dates are kept in recurring_done.
  The whole run is atomic (closed period raises and rolls back). `run` on a `--until` before start creates nothing and audits nothing.
- reconcile: write permission is required even when no --clear is given (it is a command that may record marks).
  --clear must refer to a transaction with a posting to the account on or before --date, otherwise the whole command
  fails. Cleared balance counts cleared postings dated on or before --date. Uncleared lists transaction ids
  (not postings) with a posting to the account on or before --date that are not cleared.
