**Done**
- fin/api.py (rewritten from stub): `setup(sub)` registers `serve --port N` (perm read, required port). Handler `serve(book, args)` runs `make_server(book.path, port).serve_forever()`; Ctrl-C stops it and returns `{"stopped": port}`.
- `make_server(db, port)` returns an HTTPServer bound to 127.0.0.1 (sequential, not threaded). Port 0 works for tests (read `server.server_address[1]`).
- Routes (GET: no user; POST: X-User required):
  - GET /accounts -> account list; /transactions -> txn list; /balances?at -> balance; /reports/income?from&to; /reports/balance-sheet?at; /reports/aging?at[&payables=1]; /invoices -> invoice list; /invoices/ID -> invoice show; /audit -> audit list.
  - POST /transactions (201) -> txn add; POST /invoices (201) -> invoice create; POST /invoices/ID/issue (200) -> invoice issue; POST /invoices/ID/payments (200) -> invoice pay.
  - Unknown path -> 404 `{"error"}`. UserError -> `e.status` (400/401/403) `{"error"}`.
- Order for POST: route (404) -> `Book.authorize(user, "write")` (401 missing/unknown, 403 viewer) -> JSON body parse (400) -> run via `fin.__main__.execute(db, argv, user)`. execute re-checks the command's own perm.
- Empty POST body is treated as `{}` (needed for issue, which has no body). Non-object JSON -> 400.
- Body values become CLI argv in `--name=value` form (so values starting with '-' are safe). Floats are parsed as strings (`json.loads(parse_float=str)`) to keep amounts exact.
- Invoice lines are turned into the sales CLI form `DESCRIPTION;QUANTITY;PRICE;TAXCODE` (missing tax_code -> empty).
- tests/test_api.py: 29 tests (serve parser errors, read endpoints, reports, audit, POST transactions incl. 201/401/403/400/closed period/invalid JSON/404, invoice create/list/show/issue/pay/aging, viewer/editor roles).
