Choices I made where the spec is silent (for the lead's README assumptions list):
- txn add rejects a blank --desc (after strip) as a user error.
- account add returns {name, type, currency} of the named account. Parents are not audited, only the name given.
- txn add/list return the book.txn() shape. txn list --account matches the account or its descendants (prefix + ":"), not plain string prefixes.
- balance includes every ancestor and accounts whose sums are zero (shown as "0.00"). Currencies are per account.
- fx add rejects FROM == TO and stores the rate as a plain decimal string (format(rate, "f")).
- convert requires --at; it is a read command (no --user needed).
- user add stores the stripped name; a duplicate or blank name is a user error; --role is restricted to admin/editor/viewer by argparse choices.
- period close: closing a month later than the current closed_through sets it and writes one period.close audit entry. Closing an earlier or equal month changes nothing and writes no audit entry (per spec §11). It returns the resulting closed_through. Future months are not rejected.
- audit list returns exactly seq, at, user, action, target.
