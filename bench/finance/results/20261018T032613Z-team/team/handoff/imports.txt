Assumptions (for README.md, not written by me):
- Rule account must exist when the rule is added. Rule pattern is a Python re, matched with re.search and IGNORECASE; first matching rule in add order wins.
- Import: a blank CSV row is skipped; a row with too few columns, a bad date, a bad amount or a zero amount is a UserError naming the row number, and the whole file is rolled back.
- Import description is the row's description as-is. Duplicates are keyed on (account, date, description, amount) in table imported; a duplicate counts in "skipped".
- Uncategorized fallback: Expenses:Uncategorized for outflows, Income:Uncategorized for inflows, created in book currency if missing. If its currency differs from the bank account's, the import is refused.
- Budgets: expense accounts only; amount must be >= 0; a budget covers the account and its descendants; report converts each posting to the budget account's currency at month end (via book.convert) and rounds once per budget line. Report rows are sorted by account name.
- Recurring: occurrence n is computed from the start date by index (weekly: 7*n days; monthly/yearly: add_months), so day clamping does not drift (Jan 31 -> Feb 28 -> Mar 31). Recurring add dry-runs the postings in a SAVEPOINT and refuses bad postings. Run is atomic and creates every due occurrence up to --until, tracked by the created counter per recurring row.
- Reconcile: --clear ids mark postings.cleared only on the given account's posting in that transaction; the transaction must have such a posting dated on or before --date. cleared_balance sums cleared postings up to --date; difference = statement - cleared; uncleared lists transaction ids with an uncleared posting in the account up to --date.
