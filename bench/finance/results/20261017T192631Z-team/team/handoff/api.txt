Routes (spec section 10):
- GET: /accounts, /transactions (?account&from&to), /balances?at, /reports/income?from&to, /reports/balance-sheet?at, /reports/aging?at[&payables=1], /audit (?by), /invoices (?status), /invoices/ID.
- POST (needs X-User): /transactions -> 201 (txn add), /invoices -> 201 (invoice create), /invoices/ID/issue -> 200, /invoices/ID/payments -> 200 (invoice pay).
- Errors: unknown path or non-numeric ID -> 404 {"error"}; missing or unknown X-User -> 401; ForbiddenError -> 403; any other UserError (including argparse errors, bad JSON, missing body fields) -> 400; unexpected exception -> 500 {"error": "internal error"} with traceback on stderr.
- Requests run through cli.execute with user=None for GET, so GET never checks X-User.

Assumptions (for the README):
- Server binds 127.0.0.1 only.
- --port defaults to 8000 when omitted.
- Body numbers are read with parse_float=str, so 12.50 stays "12.50" exactly.
- Posting without amount -> bare ACCOUNT, as the CLI expects.
- Invoice lines are sent as "desc;qty;price;tax_code" to docs; a description containing ";" is rejected with 400 (the CLI's line format cannot express it).
- A non-numeric invoice ID in the path is 404 (no such route), not 400.
- Body validation runs before the X-User check, so a POST with a bad body and no user returns 400, not 401.
- Log lines go to stderr through the default BaseHTTPRequestHandler logger; tests silence them.
