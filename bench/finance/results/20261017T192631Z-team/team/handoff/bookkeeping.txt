Assumptions (for README):
- Rule ACCOUNT is shape-checked at `rule add` (first segment a valid type) but not created; import creates a missing rule or Uncategorized account in the book currency.
- Import: amount zero is treated as non-negative, so it goes to Income:Uncategorized. Dedup key is (account, date, description stripped, amount normalized). Descriptions are stripped.
- Import and rule accounts must share the currency of the import ACCOUNT, otherwise UserError "row N: ...".
- Rule patterns use re.search, case-insensitive.
- Budget amounts must be non-negative. Budget target must be an expense account. Actual is converted to the budget account's currency at month end (same currency = no change).
- Recurring names are unique; a duplicate is a user error.
- Audit: import, recurring.run write an audit entry only when something was imported or created. rule.add, budget.set, recurring.add always write one.
- `loan schedule` is read-level and needs no --user, but the database file must exist (core.connect behaviour).
