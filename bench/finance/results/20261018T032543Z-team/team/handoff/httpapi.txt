**Do not redo**
- Lock: main() in cli.py starts BEGIN IMMEDIATE before the handler runs. If serve kept that transaction, per-request writers would hit "database is locked". serve therefore COMMITs main's transaction before serving and runs BEGIN again in its finally so main() can COMMIT. This is the only place that reaches into cli's transaction; cli.py is unchanged.
- The mocked serve test covers the COMMIT/BEGIN path (serve_forever returns at once, main exits 0).
- The 500 path (generic Exception -> {"error": "internal error"}) is not separately tested.

**Assumptions for README (api)**
- `serve --port` defaults to 8000 (spec says `--port N`, no default given). Binds 127.0.0.1 only. Nothing is printed while serving (modules never print); request logging is off.
- Missing required query params (from, to, at) and missing body fields -> 400 `{"error": "missing ..."}`.
- Body: empty body means {} (only the issue endpoint needs none); non-JSON or non-object -> 400.
- Auth checked before the body is parsed; POST to an unknown path is 404 before auth.
- Wrong method on a known path (e.g. PUT /accounts, POST /accounts) -> 404, not 405.
- `payables` is true unless the value is "0" or empty (so `payables=1` and `payables=true` both work).
- Extra filters beyond the spec: /transactions filters, /audit?by=, /invoices?status=, /reports/income|balance-sheet ?currency=. Bills endpoints are not exposed (spec lists none).
- Amounts in POST bodies are passed to parse_dec as strings (JSON numbers are converted with str()).
- Unexpected server errors answer 500 with a generic message; no traceback is returned or printed.
