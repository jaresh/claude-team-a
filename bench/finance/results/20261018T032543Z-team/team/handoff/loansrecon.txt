- Note for README (assumptions):
  - loan schedule: principal is rounded to cents (1000.005 → 1000.01) and must be > 0; RATE must be >= 0 (percent); MONTHS must be a whole number >= 1, no upper limit; start date is a plain date; row n is dated start + n months (keeping the day, clamped to month end). Stateless: writes nothing, no audit entry, runs without --user. It still needs an existing database file, because the CLI opens `--db` for every command.
  - reconcile is a write command: editors and admins may run it, viewers may not, and it needs --user. It is audited as `reconcile ACCOUNT` on every successful run, including runs with no --clear, since the command is registered as a write.
  - A --clear must name a transaction with a posting to exactly ACCOUNT (not to its child accounts) dated on or before --date. cleared_balance, uncleared and the clear check all use exact-account matching.
  - Clearing a transaction that is already cleared for that account is a no-op. Cleared marks persist across runs, so a later run's cleared_balance includes earlier clears.
  - Amounts go through core.fmt (half-up to cents) for output.
