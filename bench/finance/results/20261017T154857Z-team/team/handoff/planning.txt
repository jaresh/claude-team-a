- Assumptions (for README):
  - Budget amounts are in the book's base currency; `actual` converts the account's postings (account plus descendants, that month) to base at the month-end rate, rounded once. Missing rate -> user error.
  - Budget must be a non-negative amount on an existing account of type expense. `budget set` returns {account, month, budget}.
  - `recurring add` validates postings by running post_txn inside a SAVEPOINT and rolling it back, so the rules are exactly those of txn add. It also rejects an empty name, a duplicate name, and a start date in a closed period. It returns {id, name, every, start}.
  - Postings are stored as JSON in recurring.postings, as [account, amount-or-null].
  - Occurrence k=0 is the start date. Monthly and yearly use add_months(start, n, start day). Weekly uses add_days(start, 7k).
  - `recurring run` processes recurrings in id order. Occurrences already in recurring_done are skipped. A closed-period occurrence raises a user error, which rolls back the whole run. It audits recurring.run with the until date on every successful run, even when created is 0.
  - `loan schedule` rounds the principal to cents first. Interest is q2(balance * r). The last row repays the remaining balance, and total_interest is the sum of the interest column. It is a read command, but it still needs an existing book (the CLI framework opens one for every command).
