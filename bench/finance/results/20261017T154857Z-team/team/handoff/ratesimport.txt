- README assumptions to add (ratesimport):
  - fx: rate must be > 0; FROM and TO must differ; several rates on one date: the later entry wins.
  - convert: `--at` required; result is rounded half up to cents once.
  - rule: pattern must be non-empty and a valid regex; matched with re.search, case-insensitive; the
    account must exist at `rule add`; first matching rule in add order wins.
  - import: CSV read as UTF-8 (BOM tolerated); blank lines skipped; description and each field are
    stripped; amounts rounded half up to cents; a zero amount is a user error (row number reported);
    a row that is an exact duplicate (date, description, amount) of an earlier import into the same
    ACCOUNT is skipped; the whole import is one unit (any error rolls back, incl. created
    Uncategorized accounts); a row in a closed month fails the whole import; a duplicate already
    imported is skipped even if its month is closed. Uncategorized accounts are created in the book
    currency if missing. Column numbers are 0-based and must be >= 0; the audit entry is written for
    every successful import, even one that imports 0 rows. Errors name the row number.
  - If ACCOUNT's currency differs from the category account's currency, the import fails as
    "does not balance" (no cross-currency conversion on import).
