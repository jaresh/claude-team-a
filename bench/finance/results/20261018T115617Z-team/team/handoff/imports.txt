## Assumptions
- Import rows: blank lines (csv yields []) are skipped. The file is read as UTF-8 with an optional BOM (utf-8-sig). Date, description and amount are stripped of surrounding whitespace before use.
- The stored description is the stripped one. The duplicate key (account, date, description, amount) uses that stripped value and the fmt() amount.
- Errors inside import name the record number: "row N: ..." (the number counts CSV records from 1, including the header when --skip-header is given). A short row gives "row N: missing column".
- Column numbers below 0 are a user error ("column numbers start at 0").
- A file that cannot be opened or decoded is a user error: "cannot read PATH: ...".
- Uncategorized accounts and the category of a matching rule are posted in the book's currency. An import into an account in another currency fails with "unbalanced transaction" (the category account is in the book currency, so the two currencies do not balance). Spec says the category is created in the book's currency, so this follows the spec; it is not special-cased.
- A zero-amount row with no matching rule goes to Income:Uncategorized (the expense branch is value < 0 only). It still posts 0.00 on both sides.
- An empty description after stripping fails the whole import ("description required", from post_transaction).
- rule add does not reject an empty pattern (it matches every description).
