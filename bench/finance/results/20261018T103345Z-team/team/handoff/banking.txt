**Assumptions (for README)**
- rule add: the target account must already exist (transactions never create accounts). Pattern is compiled case-insensitively; an invalid regex is a user error.
- import: the bank ACCOUNT must exist. Rows with fewer columns, bad date/amount, or a zero amount are user errors (message names the row number). Blank CSV lines are skipped. Files are read as UTF-8 (a BOM is accepted). A category from a rule must share the bank account's currency, otherwise the transaction does not balance and the import fails. Default categories are created in the book currency. Dedupe uses the imported-row table only, so manually entered transactions do not count as duplicates.
- import audit: only written when at least one row was imported.
- budget set: the account must exist and be an expense account; the amount must be >= 0; setting again replaces the budget. Output: {"account", "month", "amount"}.
- report budget: actual is in the budget account's currency. Postings to descendants in another currency are converted at the month's last day, and a missing rate is a user error. Accounts with a budget but no postings show actual "0.00".
- recurring add: names are unique (user error on duplicates). Postings are validated with the txn add rules. Output: {"id", "name", "every", "start"}. Occurrence n is computed from the start (not chained), so monthly Jan 31 goes Feb 28, Mar 31, Apr 30.
- recurring run: occurrences are processed per recurring item in id order. A closed-period occurrence that is not yet created makes the whole run fail and nothing is created. The recurring.run audit entry is written only when something was created.
- rule add and import keep the spec's audit targets.
