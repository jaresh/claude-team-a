**Assumptions (for README)**
- Every user error (CLI-level UserError, including missing query params and an invoice that does not exist) returns 400, not 404. Only unknown paths return 404.
- Non-user exceptions return 500 with {"error": str(e)}.
- Invoice line text cannot contain ';' because the CLI line format is DESCRIPTION;QUANTITY;PRICE;TAXCODE. Such a line is a 400.
- Invoice lines and postings accept JSON strings or numbers; booleans, objects and arrays are a 400.
- Server binds to 127.0.0.1 only. There is no --host option.
- Only the listed routes exist. POST /bills, user add, and period close are not exposed.
- Extra query params not in the spec: /transactions?account, /invoices?status, /audit?by, /reports/aging&payables=1 (or true).
- Each request opens its own SQLite connection (via cli.execute), so the ThreadingHTTPServer threads do not share a connection.
