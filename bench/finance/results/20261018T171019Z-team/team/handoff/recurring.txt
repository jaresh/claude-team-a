Assumptions
- Rule names are not unique (no schema constraint; run keys on rule id). A blank name is a UserError.
- At least one --posting is required (explicit error); the posting rules come from core.post, so
  a single posting or unbalanced postings fail as in txn add.
- Validation posts on the start date, so a start in a closed period is refused at add time.
  Later occurrences that fall in a closed period fail the whole `recurring run`.
- --every is restricted by argparse choices (an invalid value is a UserError, exit 2 / 400).
- Stored postings: [[account, money-string]] or [account, null] for the auto-balanced posting.
- `recurring run` audits once even when it creates nothing (rule: every successful write
  audits exactly once). Target is the until date in ISO form.
- Run creates occurrences in rule id order, then date order; each one recorded in recurring_runs
  with its txn id.
