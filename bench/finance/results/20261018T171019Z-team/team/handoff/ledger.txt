Assumptions (decisions where the spec was silent)
- txn add with no --posting: UserError "txn add needs at least one --posting" (before core.post).
  One posting given: core.post's "two or more postings" error.
- txn add --desc and --date are required (argparse).
- txn list --account, --from, --to are checked with `is not None`. Account matching uses
  core.in_prefix in Python on each txn's postings (whole segments only: "Exp" does not match
  "Expenses").
- balance: an account appears if it has any posting on/before the date, even if its sums are
  zero ("0.00", never "-0.00"). Ancestors are added via core.ancestors.
- fx add: codes must be 3 ASCII letters, stored uppercase. RATE stored as given (stripped of
  surrounding spaces) and returned as that string. RATE must parse by core.dec and be > 0.
  FROM equal to TO is allowed (convert then ignores it).
- fx add audit target "FROM/TO" (uppercase).
- convert CLI: AMOUNT via parse_amount (at most two decimals); --at is required; output
  amount is money(unrounded result), currency TO.
- convert rule: same code returns the amount unchanged. Otherwise latest FROM->TO rate with
  date <= at (ORDER BY date DESC, id DESC); if none, latest TO->FROM rate inverted as
  amount * (1 / rate) in Decimal. Else UserError "no exchange rate FROM to TO on or before DATE".
  The inverse is computed as (1 / rate) first, then multiplied, as the plan says.
- Module `convert` returns an unrounded Decimal; reports must round with cents() per account.
