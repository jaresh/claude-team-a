Design choices the lead may want to know about
- fx add rejects FROM == TO with UserError ("currencies must differ"). Same-currency convert needs no rate and returns the amount unchanged (tested).
- fx add stores the rate string exactly as given (after validation via core.parse_decimal, must be > 0).
- txn add amounts go through core.parse_amount, which rounds to cents (core behaviour).
- account add rejects names containing '=' or empty segments (e.g. "Assets::X") in addition to core.account_type's top-level check, because posting parsing splits on the first '='.
- txn list --account matches with `account = P OR substr(account,1,len(P)+1) = P+":"` (no LIKE, so '_' and '%' in names are literal). Each returned txn is the full txn (all postings), via core.get_txn.
- Parent accounts created implicitly by account add take the currency given on that call (core.ensure_account behaviour); not changed.
