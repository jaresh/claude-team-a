  - ROUTES: GET /accounts, /transactions (account, from, to), /balances (at), /reports/income (from, to, currency), /reports/balance-sheet (at, currency), /reports/aging (at, payables=1|true), /invoices (status), /invoices/{id}, /audit (by); POST /transactions (201), /invoices (201), /invoices/{id}/issue (200), /invoices/{id}/payments (200).
  - GET needs no X-User. POST: no header or unknown user -> 401; cli.authorize role failure -> 403; UserError or sqlite DatabaseError -> 400 {"error"}; unknown path or method -> 404.
  - Each request opens its own connection and runs in one BEGIN IMMEDIATE transaction (same as cli.run). The role check runs inside that transaction; COMMIT on success, ROLLBACK on any error.
  - Handlers reuse the CLI functions (ledger.cmd_*, reports.cmd_report_*, billing.cmd_*) through argparse.Namespace. Invoice create/issue/pay call billing.create_invoice, issue_invoice, pay_invoice directly.
  - make_server(db, port) returns a ThreadingHTTPServer bound to 127.0.0.1 (port 0 picks a free port). serve(db_path, port) wraps it with serve_forever; it exits 2 if the db file is missing, as in the CLI.
  - Request-level missing db or non-fin db -> 400 (the CLI would exit 2 for the same case).
