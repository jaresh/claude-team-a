- Assumptions (put in the README "assumptions" list, not implemented elsewhere):
  - import: the ACCOUNT is assumed to be in the book currency. A foreign-currency account fails with core's "does not balance" error, and nothing is imported.
  - import: duplicate key is (account, date, description, amount text). An import in which every row is skipped still writes its one audit entry.
  - import: a rule's target account is not checked at `rule add`; import auto-creates it via ensure_account.
  - report budget: actual = sum of the month's postings to the account and its descendants, converted to the book currency at month end. Only the book currency is supported (no --currency).
  - loan: the last row's payment is balance + interest, so it can differ from the level payment by a few cents.
  - recurring: a blank posting amount is stored as null and is resolved at each run.
  - recurring run: all pending occurrences across all recurring items are checked before any is written; closed periods fail the whole run.
- Known test coverage gaps: no test for `report budget` in a foreign currency, since that is not supported; no test for `rule add` with a nonexistent account (it is allowed by design).
