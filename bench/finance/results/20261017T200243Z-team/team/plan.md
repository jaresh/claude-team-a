## Contract (already written by lead; READ fin/core.py, fin/ledger.py, fin/cli.py, tests/helpers.py first)
- Use `python3`. Each feature module has `add_parsers(sub)` registering argparse commands. Use `core.group(sub, "report")` for command groups (report, invoice, ...) so modules share a group; top-level commands use `sub.add_parser(name)`. Register handlers with `core.command(parser, func, perm)`, perm `'read'|'write'|'admin'`. Handler: `func(ctx, args) -> JSON-able doc` (ctx.conn sqlite, ctx.currency, ctx.audit(action, target)). Raise `core.UserError` for every user error (the CLI exits 2, rolls back everything). Never print. Every write handler calls `ctx.audit(...)` exactly once per spec section 11.
- Money: `core.D`, `core.q2`, `core.fmt` (strings in JSON). Dates: `core.date_str`, `parse_date`, `month_str`, `add_months`, `month_end`. Posting: `core.post_txn(ctx, date, desc, [(account, Decimal|None)])` (checks closed periods, balance) returns txn doc; `core.parse_postings`, `core.ensure_account(ctx, name, currency=None)`, `core.direct_balances(conn, frm, to)`, `core.convert(conn, Decimal, frm, to, date)`, `core.rate`. `ledger.rolled_balances(conn, at)`.
- Tables in core.SCHEMA already exist: rates, rules, imported, budgets, recurring, recurring_done, cleared. Tables for invoices/bills/tax/customers/vendors: define in your module's `SCHEMA` string (`CREATE TABLE IF NOT EXISTS`); tools.py, billing.py, reports.py each may define SCHEMA.
- Tests: `unittest`, subclass `tests.helpers.FinTest` (see it), file per task in tests/. Each test creates data through the CLI. Cover success paths, exit-2 error paths (nothing changed), JSON shapes exactly as in the spec. Reuse helpers; don't edit core.py/ledger.py/cli.py/helpers.py — if you find a bug there, log it in `.claude/team/changes.md` and handoff and work around it.
- Run in the repo root. Write the handoff file before finishing (Done / Next step / any bug found, brief).
