  - `vendor add` output is `{"name", "terms"}`, same shape as `vendor list` rows; terms must be an integer >= 0 (argparse int, default 30).

  - `bill create` needs at least one `--line` (argparse required). Each line must have exactly 4 `;`-separated parts; description must be non-empty; amount must parse and be >= 0.
  - Line ACCOUNT must exist and be type expense or asset (asset account type is `asset` in the accounts table).
  - Empty TAXCODE means no tax (`tax_code: null`, tax `0.00`), same as invoices.
  - Per-line tax = round2(net * rate / 100); bill tax = sum of line taxes; total = net + tax.
  - `Assets:TaxReceivable` is posted only when the bill tax is non-zero; `Liabilities:Payable` is created with ensure_account on every bill create.
  - Bill ref must be unique per vendor (checked before insert; the UNIQUE constraint is not relied on).
  - `bill pay`: amount is round2'd and must be > 0; payment account must be type asset; a fully paid bill is a user error ("already paid"); amount above balance is a user error. The payment date is not checked against the bill date.
  - Payment rows go into `payments` with kind 'bill', doc_id = bill id, amount = fmt(amount), account, txn_id. Status is stored as `partial` or `paid` and recomputed on each pay.
  - `bill list --status` uses argparse choices open/partial/paid (bad value -> user error).
