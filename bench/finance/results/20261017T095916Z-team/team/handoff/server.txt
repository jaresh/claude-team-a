**Do not redo**
- Checked that core.Book.rollback() is safe on a closed connection (it catches sqlite3.Error, which covers
  ProgrammingError), so an interrupted serve() unwinds through run() without a traceback. Verified: a server started
  from a Python parent with SIGINT sent exits with returncode 130 and prints only the "serving on" line.
  Pitfall: a server started with `&` from a non-interactive bash inherits SIGINT as ignored, so SIGINT does nothing
  and the process must be stopped with SIGTERM. That is a harness artifact, not a server bug.
- Checked that cli.run() calls book.commit() after the handler returns, which would fail on a closed connection,
  so serve() never returns normally. It only exits by exception (KeyboardInterrupt or kill). Do not add a return.
- Parser.error raises UserError, so argparse failures become 400 without printing. A positional amount beginning
  with '-' is rejected with 400 before argparse sees it (to avoid "--help" and similar). Option values use the
  `--name=value` form for the same reason.
