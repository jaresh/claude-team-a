- fin/reconcile.py:
  - Service fn `reconcile(ctx, account, date, balance, clear_ids)` returns the spec sec 16 dict (account, date, statement_balance, cleared_balance, difference, uncleared). Takes ctx, so the API can call it directly.
  - Handler `cmd_reconcile(ctx, a)`; `register(sub)` adds the top-level command `reconcile ACCOUNT --date --balance [--clear ID ...]`, with set_defaults(write=True, admin=False).
  - Helper `_parse_ids` (private) validates --clear values as integers and dedupes them.
- Behaviour:
  - Account must exist; date, balance and ids are validated.
  - Every --clear id is checked (posting to exact account on or before DATE) before anything is written. Any failure is a UserError and nothing is marked.
  - Marks go into `cleared` with INSERT OR IGNORE.
  - Audit `reconcile` (target = account) is written inside the service fn, only when clear_ids is non-empty. The API therefore gets it too.
  - cleared_balance = sum of cleared postings to ACCOUNT dated on or before DATE. uncleared = ascending distinct txn ids with uncleared postings to ACCOUNT on or before DATE.
