**Decisions and deviations (lead should check)**
1. Dedup `n` column: the plan's occurrence-index scheme would import the second of two identical rows in one file, which contradicts spec sec 5 ("including repeats within one file"). I followed the spec: one stored row per key, `n` always stored as 1. The column is unused.
2. Zero-amount rows go to Income:Uncategorized (spec only covers negative and positive). Negative goes to Expenses:Uncategorized.
3. Empty rule pattern is rejected (spec silent).
4. An import is always audited, even when imported = 0 (one `import` entry per successful call).
5. If the rule account (or the account being imported into) has a different currency than the other side, add_txn fails with "does not balance" and the whole import rolls back. This is a UserError, not a bug in this module, but the message is unclear.
