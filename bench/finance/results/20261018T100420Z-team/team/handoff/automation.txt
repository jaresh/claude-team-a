- Lead to note for README assumptions (automation section):
  1. Import is one transaction per file: any bad row or closed-period row fails the whole file.
  2. Duplicate detection key is (account, date, description, amount); repeats inside one file are skipped too. Rows are tracked in imp_rows.
  3. Uncategorized default is Expenses:Uncategorized for negative amounts and Income:Uncategorized for positive ones; these accounts are created with ensure_account.
  4. The first matching rule wins (rules in insertion order, case-insensitive regex, pat.search on the description).
  5. A rule's account must exist when the rule is added; its pattern must be a valid regex.
  6. An import's category account must use the same currency as the import account.
  7. Budgets: only accounts of type "expense"; amount >= 0; one row per (account, month); actual sums the month's postings to the account and its descendants, converted to book currency at month end.
  8. Recurring: monthly/weekly/yearly; each occurrence is computed from the start date, so month ends clamp (Jan 31 -> Feb 28) and do not drift. Postings are validated at add by a dry post inside a SAVEPOINT, which also rejects a start in a closed period. Run is idempotent via auto_occurrences; a closed-period occurrence fails the whole run.
  9. Audit: rule.add (pattern), import (account, only when rows were imported), budget.set ("ACCOUNT MONTH"), recurring.add (name), recurring.run (until date, only when something was created).
