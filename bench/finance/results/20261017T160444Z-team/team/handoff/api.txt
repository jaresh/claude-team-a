Route table
- GET /accounts, /transactions[?account&from&to], /balances[?at], /reports/income?from&to, /reports/balance-sheet?at, /reports/aging?at[&payables=1], /invoices[?status], /invoices/ID, /audit[?by]. No X-User needed.

- Unknown path or method/path mismatch -> 404 (checked before auth).

Behaviour
- Order: route match (404) -> Book.open -> check_permission for writes (401 unknown or missing user, 403 viewer) -> body parsing (400) -> feature function -> commit. UserError -> rollback and 400 (or e.status). Other exceptions -> 500 with message.
- Public entry point: fin.api.handle(db, method, target, user, raw=b"") -> (status, data). Each call opens its own connection.
- Server: ThreadingHTTPServer bound to 127.0.0.1 only. Each request uses its own Book connection; the CLI's book is unused. Access log is silenced. Startup line goes to stderr; the command returns {"port": N}, which the CLI prints.

Assumptions (spec silent or ambiguous)
- Binding is 127.0.0.1 only, not 0.0.0.0.
- Invalid invoice id in the path (e.g. "abc") -> 400, same as an unknown id (get_invoice raises UserError for unknown id).
- Payables flag is `payables=1` on /reports/aging; any other value means receivables.
- Missing required query params (e.g. /reports/income without `to`) -> 400 with "missing query parameter: to".
- Bad body (non-JSON, non-object, missing field) -> 400 with a message; the permission check runs first, so an unauthorized caller never sees body errors.
