Assumptions (where the spec is silent or I chose):
- import: each row is validated before any insert (bad date, bad amount, too few columns, zero amount, check_open on the row's date, currency mismatch with category). Any failure imports nothing.
- import: dedupe key is (date, description, amount) per account, checked against the `imported` table and within the same file. Repeat import skips all rows.
- import: uncategorized rows go to Income:Uncategorized (positive) or Expenses:Uncategorized (negative), created on demand.
- import: blank CSV lines are skipped. Column indexes are 0-based and must be >= 0.
- budget: only expense accounts can have a budget. Setting again for the same account and month replaces the amount.
- budget report: actual = sum of postings in the month to the account and its descendants, in the account's currency (no conversion). remaining = budget - actual (can be negative).
- recurring: occurrences start at `start` and are computed as start + k periods (monthly via add_months, so Jan 31 gives Feb 28 and Mar 31; weekly +7k days; yearly add_years, so Feb 29 gives Feb 28 in non-leap years). Occurrences already in recurring_done are skipped, so repeated runs are idempotent.
- recurring run: check_open is checked for all due occurrences before any post, so a closed period creates nothing.
- loan: payment = principal * r / (1 - (1+r)^-n), rounded to cents; r = annual % / 1200; with rate 0, payment = principal / n. The last row pays the remaining balance plus its interest, so balance ends at 0.00. Rate must be >= 0, principal > 0, months >= 1.
