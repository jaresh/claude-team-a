**Assumptions**
- Bill line ACCOUNT must already exist and be an expense or asset account (not auto-created). Lines should be in the book currency; a line in another currency fails as an unbalanced transaction (user error).
- Line format is exactly 4 fields `DESCRIPTION;AMOUNT;ACCOUNT;TAXCODE`; description must be non-empty; empty tax code = no tax.
- Line net is rounded half up to cents; line tax = round(net*rate/100); bill tax = sum of line taxes; total = net + tax.
- Tax receivable (Assets:TaxReceivable) and Liabilities:Payable are created with ensure_account if missing; TaxReceivable is only created/posted when bill tax is non-zero.
- Negative or zero bill line amounts are not rejected (spec is silent).
- Vendor terms: argparse int, must be >= 0. Vendor name is stripped and must be non-empty.
- Bill due = bill date + vendor terms days.
- `bill pay` rejects: non-positive amount, amount above balance, already-paid bill, non-asset or unknown payment account, bad date, closed period. Payment date is not checked against the bill date.
- `bill pay` prints the updated bill (same as invoices print the invoice).
- `bill list --status` is validated against open/partial/paid; an invalid status is a user error.
- Audit: `vendor.add` target = vendor name; `bill.create` and `bill.pay` target = bill id.
- Tests insert the VAT20 tax code directly into `taxes` via sqlite3 in setUp (no dependency on `tax add`).
