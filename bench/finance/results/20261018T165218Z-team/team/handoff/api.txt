ASSUMPTIONS (for README)
- Query params beyond the plan's list are not supported (no account filter on /transactions,
  no status filter on /invoices). Unknown query params are ignored.
- payables=1 (or true) means bills; any other value or none means invoices.
- POST checks in this order: route (unknown path -> 404), then X-User and role (401/403), then
  the body (bad JSON or wrong shape -> 400). So a bad body from an unauthorized user gets 401/403.
- POST /invoices/ID/issue ignores any body. Other POSTs need a JSON object body.
- Unknown method on a known path (for example DELETE /accounts) -> 404 with the same body as
  an unknown path.
- Unexpected (non-FinError) exceptions -> 500 {"error": "internal error: ..."}; the server keeps
  running.
- The request log is silenced (log_message is a no-op) so the terminal stays quiet.
- serve binds 127.0.0.1 only; --port defaults to 8000 (port 0 picks a free port). With --json,
  serve prints `null` after it stops (Ctrl-C).
- Responses are compact JSON (same as --json), Content-Type application/json.
