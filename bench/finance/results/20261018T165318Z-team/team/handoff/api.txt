Assumptions
- Port defaults to 8000; server binds 127.0.0.1 only.
- Content-Length is read; a missing or zero length is treated as an empty body, which becomes {} for POST.
- Unknown query parameters are ignored. For /reports/aging, only payables=1 turns on --payables.
- A missing database file gives 400 "no database: PATH" before any access check (connect() would otherwise create an empty file).
- Access order for POST: route match (404) -> access check (401 missing or unknown user, 403 viewer or non-admin on admin-only actions) -> body parse (400) -> CLI run. A CLI error exit (code 2) becomes 400 with the stderr message minus "error: ".
- Error bodies are JSON {"error": "..."}; an unexpected exception gives 500 {"error": "internal error"}.

POST argument mapping
- POST /transactions {date, description, postings:[{account, amount}]} -> `txn add --date=D --desc=TEXT --posting=ACCOUNT=AMOUNT` per posting. A posting with amount absent or null becomes `--posting=ACCOUNT`. postings must be a list of objects with an account; non-string fields give 400. Success 201 with the transaction JSON.
- POST /invoices {customer, date, lines:[{description, quantity, price, tax_code?}]} -> `invoice create --customer=C --date=D --line=DESC;QTY;PRICE;TAX` per line (empty tax when absent). Lines need description, quantity and price. Any field containing ";" gives 400. Success 201 with the draft invoice.
- POST /invoices/ID/issue -> `invoice issue ID`. Success 200.
- POST /invoices/ID/payments {amount, date, account} -> `invoice pay ID AMOUNT --date=D --account=A`. Success 200 with the invoice.
