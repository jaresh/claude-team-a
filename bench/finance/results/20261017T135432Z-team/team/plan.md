**Check**: `python3 -m unittest discover -s tests` (from repo root).

## Contract / Conventions (lead already wrote; READ fin/core.py and fin/cli.py first, ~250 lines)
- fin/core.py is shared: `D` (parse decimal), `q2`/`fmt` (round/format money), `parse_date/date_str/parse_month/month_end/add_months`, `split_posting`, `UserError`, `Book` (account(), ensure_account(), add_account(), post_txn(date, desc, [(acct, Decimal|None)]) -> txn dict, txn(id), check_open(date), rate/convert, audit(action,target), meta). The full DB schema (all tables, incl. invoices/bills/payments/cleared/rules/budgets/recurring) is in core.SCHEMA: use those tables, do not create tables. Do not edit core.py/cli.py/tests/helpers.py: if you need a change, put it in your handoff.
- Never re-implement parsing, rounding, formatting, date math, posting. Money is Decimal, stored as text; output via fmt(). Errors: raise UserError("message") only; no prints, no sys.exit.
- A module fin/<name>.py defines `COMMANDS = [Cmd(words, setup, handler, perm), ...]` (see cli.py). `setup(parser)` adds argparse args (use dest = the flag/positional name with '-' -> '_'; e.g. --date-col -> date_col; --desc -> desc; --posting action="append"; --clear action="append" type=int). `handler(book, args)` returns JSON-able data (the same document for --json; cli prints it). perm: "read" (no data change), "write", "admin". Handlers call `book.audit(action, target)` exactly once on success when they change data (action names in spec section 11); they do not commit (cli does). Put reusable logic in plain functions of the module taking `book` (e.g. `def add_txn(book, date, desc, postings)`), thin handlers.
- Module -> file mapping (cli.MODULES): ledger, admin, banking, schedule, reports, invoicing, billing, tax_aging, api. Each task owns only its fin/<module>.py and tests/test_<module>.py. Tests subclass `helpers.FinTest` (`from helpers import FinTest`; self.init(), self.ok(*args) -> JSON, self.fail(*args), self.run_cli). Before other modules exist, create what you need via CLI commands of your own module or direct SQL through `book.conn` (core.Book(self.db)); in tests that need `txn add`, use the real command (ledger will exist after wave 1 merge; if it does not yet, post with Book.post_txn directly and commit).
- Raw balance of an account incl. descendants: sum of Decimal(postings.amount) where account = X or account LIKE 'X:%' (escape not needed; names have no % or _ ... treat as plain, but compare with `account = ? OR account LIKE ? || ':%'`).
- Each task: write unit tests in its own tests file, run `python3 -m unittest discover -s tests` before finishing; handoff in .claude/team/handoff/<task>.txt (Done / Next step / anything the lead must change). Log edits to shared files in .claude/team/changes.md (you should have none).
