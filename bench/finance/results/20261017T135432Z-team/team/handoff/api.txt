**Decisions (spec 10 was silent; lead may override)**
- Body validation runs before the auth check, so a viewer sending a malformed body gets 400, not 403. execute() does the auth and role checks.
- Values go to argparse as `--name=value`, so a description like "-x" or a negative amount is not read as an option.
- Invoice line fields containing ';' are a 400 (the line format cannot carry them).
- GET ignores X-User. Only POST passes --user to execute.
- Access logging is silenced (log_message is a no-op) so tests and the server stay quiet. Errors are returned as JSON.
- Bills are not exposed (GET /bills and bill POSTs are not in spec 10). Add them if wanted.
- Reports, balances and the trial balance: only the spec 10 routes are mapped. report networth, trial-balance, ledger and report tax are not exposed.
