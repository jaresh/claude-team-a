Known limitations to note for the lead:
1. Multi-currency rounding: each account's per-currency sums are converted and rounded, then the rounded values are summed. When a report mixes currencies, totals can differ from unrounded totals by a few cents. The balance-sheet identity (assets = liabilities + equity) and trial-balance debit = credit hold exactly for single-currency books, and the tests cover that case. Documented in the balances() docstring.
2. Retained earnings = sum of shown income minus sum of shown expenses up to --at, from the rounded per-account amounts. total_equity includes it.
3. Loan schedule needs an initialised book, because the read perm goes through core.execute, which enforces the initialised check. The schedule itself does not use the book.
4. from > to is a user error (exit 2, stderr "error: ..."). The networth command does the same check on months.
5. Ledger converts each posting at the --to date (per-posting conversion), not at each posting's own date. Opening balance is also converted at --to.
6. Balance sheet, networth and trial balance include only accounts that have postings in range. Parent accounts (auto-created by ensure_account) never appear as rows.
